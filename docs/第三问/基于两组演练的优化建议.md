# 基于两组实际演练的优化建议

日期：2026-09-11。本页为代码核查与既有日志诊断，不代表已实施优化或已测得性能提升。比较基线见[两组演练评估](两组演练评估_s1_s2.md)。

## 1. 建议次序

当前保留方案一作为主基线。优先试验方案二按频道停止已足够精确的检测，以及方案一结合后续搜索站的路线调度。前者规则较明确，后者对应方案一最大费用来源。不能据当前未配对的12局预先判定优化后哪套方案获胜。

| 优先级 | 优化内容 | 当前证据 | 尚需验证 |
|---|---|---|---|
| 第一批 | 方案二：具备双站观测与安全清除证书后，按频道停止固定检测 | 六局共370次固定检测发生在已有证书之后 | 少测后的区域、清除位置和路线变化是否抵消费用节省 |
| 第一批 | 方案一：目标处理顺序与后续搜索站联合规划 | 移动占总费用约81.5%；当前每站处理完已知目标，再推进搜索 | 是否减少折返，是否增加定位次数或拖延未知频道搜索 |
| 第二批 | 方案一：顺路检测按预计信息价值筛选 | 平均每局51.33次顺路检测；目前为600米间距与最多4频道的启发式 | 节省检测是否造成后续绕行、补测增加 |
| 第二批 | 两方案：集中清除顺序、清除点与后续路线共同优化 | 方案二前往证书清除点平均行走7177米 | 固定安全点的路径改良，以及在安全区域内选点的收益 |
| 后续 | 负观测约束利用、几何细化和候选采样改进 | 负观测已保存，但主要定位仍使用保守凸外包 | 复杂度、边界安全与实际净收益 |

## 2. 方案二最具体的机会：达到清除精度后停止继续测该频道

当前固定扫描会检测状态为unknown或found的频道；已经可以安全清除、但还没有走到目标附近的频道，仍处于found，因此后续固定站会继续检测它。现有原地清除只处理当前站点本身能覆盖整个候选区域的目标，不能替代“已经定位完成”的频道标记。

按原日志每次动作发生前的信息核查，同时满足以下两个条件后，又发生的固定检测共有370次：已获得两个不同站点的方向观测；候选区域的最小覆盖圆半径不超过19.5米。六局分别为29、71、49、71、85、65次，平均61.67次/局，仅检测费用就是308.33秒/局。

这些检测未必完全没有价值：它们可能进一步缩小区域，使后续安全清除位置更灵活。因此308.33秒是原日志中这类检测对应的费用，不是删掉检测后的净节省，不应直接从原成绩中扣除并宣布反超。

第一版候选规则可保留14站布局，增加“已定位、待清除”的频道状态，默认跳过该频道后续固定检测；保留已有安全区域供清除。没有达到证书的目标继续检测，未发现频道继续执行覆盖排除。对已定位目标，只有预计额外测量带来的路线收益大于检测、切换费用时才继续测。

这里不是“测到两次就停止”，两次方向观测仍可能无法满足清除精度；必须同时核查覆盖圆判据。官方结果文件里的目标总数仅用于事后评估，不作为策略运行时已知信息或提前退出依据。

## 3. 方案一的主要机会：减少前往测向点的行走与跨目标折返

六局平均路程18727.66米；按每一段移动的终点动作分类，前往追加测向点10595.38米，前往搜索站5970.09米，前往证书清除点1732.19米，前往有限方格覆盖点430.00米。前往测向点约占总路程56.6%。此处按终点用途归类，不能把10595米全称为“测向造成的可省绕路”，其中也包含跨目标位移。

代码当前按单个目标的完成费用上界选择处理对象；候选测向位置的评分包含到站、检测及该目标后续处理，但没有显式计入完成后如何衔接下一个目标或搜索站。每个搜索站处理完当前所有已知目标，再前进到下一固定站，也可能让路线折返。

建议先做有限的两步比较：比较“现在服务目标A再去下一站”“先去下一站再服务A”，以及已知目标A、B的两种服务顺序。评分包含全部移动、检测、切换和清除费用；只执行第一步，收到反馈后重新计算。给未知频道的搜索保留明确进度约束和有限延后次数，不因局部贪心而漏扫。

观测点也应评价与后续任务的衔接：两个点对当前目标的效果接近时，优先考虑更有利于下一搜索站或其他目标的位置。仍须逐个检查可靠接收条件和清除覆盖证书，不能以路线短替代几何可行性。

## 4. 顺路检测应保留，但改为有选择地执行

方案一平均每局有51.33次顺路检测，在现有日志中没有额外位置移动，但每次仍收取5秒检测费和必要的1秒频道切换费。不能把“顺路”理解为免费。

当前用已测位置间距600米、优先已发现频道、每站最多4个的启发式选取。可进一步比较追加信息能否使目标直接可清除、明显减少未来绕行，或推进未发现频道的覆盖排除。已经足够精确的目标，默认不再仅为缩小区域而检测；价值接近的候选可优先当前频道。

不建议直接整体关闭顺路检测：既有30个本地成对场景中开启设置平均较快，说明它确实可能节省后续路程；该证据与本轮12局实际演练分开使用。需要比较现有规则与按价值筛选的规则，而不是凭51次这一数字断言都多余。

## 5. 清除路线和几何方面的次级改进

方案二扫描后大多目标已具安全清除区域，适合先在已知安全点上调整访问顺序，例如交换两段路线，然后每步重算。原版按当前单目标完成费用贪心选择，未进行全路线改良。若方案一同一时刻已有多个可清除目标，也能复用。

当前clear_point沿“当前位置到最小覆盖圆心”的线段寻找首个安全点，已比直接去圆心省路；它还不是整个安全清除区域中离当前位置最近的点。可进一步在所有顶点的19.5米圆盘交集中求最近点，或结合下一目标选点。finish_bound当前按去圆心估算小区域处理费用，也可与实际执行的安全点算法对齐。这属于预计费用和选点细化，收益需测量。

无信号和清除失败对应的圆形排除约束目前单独保存；主要可靠接收、清除证书和测向评分仍基于凸外包。未来可用保守分区利用这些约束，减少已经排除区域引起的过度保守。但非凸区域处理更复杂，不宜优先于明确的重复检测和路线调度。

本组方案一只有两次失败清除，直接失败费用合计6秒、平均每局1秒；移动费用另计。追求零次失败清除不应压过总费用目标。程序本地平均运行约1.5秒，当前也不应把执行速度微优化作为主要提分手段。

## 6. 后续验证安排

先保留现有版本与原始日志，分别实现单项改动。方案二先比较是否跳过已具证书频道；方案一先比较是否加入后续站点的路线代价。每次在同一批本地构造场景进行成对对照，同时核对全清、费用、路程、检测次数与几何证书。

再使用没有参与调参的新场景验证，并交替安排更多官方演练；若无法官方同场景重放，继续按目标数分层报告，保留失败和中断。只有净总费用改善且完成保证未受损，才考虑替换默认配置。本轮未实现上述策略修改，也未运行新演练或正式测试。
